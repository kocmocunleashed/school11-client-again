Visitors download less JavaScript, the code that makes the page interactive, and less CSS, the code that styles it. The browser also uses the content already delivered with the page instead of immediately downloading it again.

What was changed?

REMOVED

Leftovers from the admissions lookup panel

The panel was already removed from the admissions page in commit 088101f. Its unused component and dedicated styles are now deleted. The PDF guide stays available.

The lookup API, private application records, and admin application tools remain. They have independent contracts and tests; removing an interface does not prove the backend has no external users.

REMOVED

Five unused starter images and unused props

The Next.js starter SVGs had no references and were deleted. The news browser no longer accepts an ignored article-list prop, and the header no longer accepts an unused city prop. School images and published content remain.

These deletions simplify maintenance. The unused SVGs were not downloaded by the app, so deleting them does not contribute to the bundle savings.

REMOVED

Unused query helpers and display variants

Ten database query helpers had no consumers: three calendar queries, three news queries, two achievement queries, one featured-teacher query, and one course-by-slug query. The app already reads these collections through its shared public dataset. They are removed, along with the unused featured-teachers display mode and a legacy demo-news helper. Its existing test now checks the public projection used by the app.

These helpers were already absent from reachable bundles. Removing them reduces maintenance work rather than visitor download size.

IMPROVED

Demo code loads only when needed

The browser-local demo database and its seed records used to be imported by every public page. They now load through a dynamic import only in preview mode. Shared event names live in a small separate module.

Live visitors do not need this demo code. Local preview still loads it after the page arrives and retains saved demo edits.

IMPROVED

Content refreshes do less duplicate work

A live page now starts with the content sent by the server. It no longer immediately requests the same full dataset on mount, and it adopts new server-delivered data when the server payload changes. Navigation brings a fresh server-rendered page projection. Focus refreshes the current page, while overlapping refreshes share one request. Leaving the provider cancels the request and ignores late responses. Failures keep the last successful content and allow a later retry.

IMPROVED

Styles load with their owners

Admin styles now load under the admin layout. Calendar, management-card, and homepage timeline styles load with their components. The public calendar no longer carries admin form styles. Colors and visible layouts are preserved.

KEPT

Reachable school workflows

Timeline, podcasts, course catalog, calendar, Hall of Fame, news filters and dialogs, admissions guide, analytics, authenticated CMS, and local CMS preview remain. Each dependency in the package manifest has an existing use; no package was removed.

What the live-site review showed

Reviewed school.leoh.site using agent-browser. This review inspected the existing deployment; the changes in this report are local.

  • Homepage: timeline, four podcast links, courses, Hall of Fame highlights, and news are reachable. These are reasons to keep the features.
  • About: the timeline includes test-like titles, including “codiene crazy” and “hey new test for 2.0”. These need an editor’s review in the CMS. No live content was changed.
  • Courses: the calendar is present, but the inspected October 2026 dates show no public events. An empty calendar alone does not establish that the feature is unused.
  • News: category and sort controls are present. An article dialog opened and closed with Escape.
  • Achievements: searching for “Амарсайхан” returned two records. Repeated student records can represent different competitions.
  • Admissions: checked for the guide and absence of the removed results panel.
  • Mobile: the menu opened at 390px width, closed with Escape, and restored focus to the menu button. No horizontal overflow was observed.
  • Network: the inspected live Courses document recorded two /api/site-data requests, each about 18.3 kB transferred and roughly 0.5 seconds long in this session. This is a session observation, not a benchmark.

Browser clicks and navigation sometimes needed a follow-up check before the expected state appeared. Programmatic DOM activation was used for the news dialog. A navigation wait timeout was not treated as proof that the site was broken.

  • 87 automated tests pass. They cover CMS projection, private data exclusion, authentication, validation, calendar logic, podcasts, timeline, uploads, cache invalidation, refresh deduplication and cleanup, page projection, image policy, and idle animation behavior.
  • Production build, lint, type check, and secrets check pass. The final stylesheet ownership changes were included in a fresh production build.
  • 10 production integration checks pass.   • Local browser checks: article bodies on demand, missing-article error and retry, browser-local preview bodies without a network request, unpublishing an open preview article, and restoring the preview, timeline selection, calendar month navigation, news dialog and Escape, About card layout, and admin calendar styling were checked. Public Courses did not load admin styles; the admin route did.
Technical details and how to repeat the measurements

Baseline: clean worktree at 088101f. Both builds used the same Bun dependencies, Next.js 16.3.4, and local unconfigured preview data. Each route’s HTML was read to collect unique script and CSS URLs; those files were fetched and measured before compression and with gzip level 9. A second implementation of the measurement reproduced every recorded value.

Static asset measurements exclude images, fonts, inline HTML, route prefetching, and files requested after hydration. The page-document table separately measures HTML, including embedded server data. Preview mode downloads the deferred demo code after mount, so its total session transfer is not reduced by the full initial JavaScript saving. Configured production pages do not request that demo module. The server still caches the complete dataset, but each public page sends its own projection to the browser. The legacy full-dataset API remains for compatibility; page refreshes use the scoped endpoint.

Implementation plan

The three technical steps below are implemented and verified. Published-content decisions remain an editorial review.

Implemented: send each page only its content

Page-specific projections now use the existing cached dataset. Homepage and About copy are also scoped so principal messages do not travel to the homepage and hero text does not travel to About. Providers live in each public page, and full article bodies load only when opening an article. CMS invalidation and private-data exclusions remain. All six route projections, article loading, unpublish/delete, and cache reuse passed checks.

Implemented: resize approved images

The existing Next image optimizer now handles public Supabase storage, YouTube thumbnails and school Hall of Fame portraits. Direct delivery remains for other CMS origins, data/blob previews and GIF/SVG files. Fixed-size portrait sources keep the complete 172-record archive smaller than before the plan.

Implemented: stop idle animation frames

Hall of Fame scrolling is scheduled only when the rail is visible, the tab is visible, and hover/focus are not pausing it. Manual controls, end-of-list stopping and reduced-motion support remain. Tests verify cancellation and resumption without a time jump.

Editorial and deployment follow-up

Review test-like history entries in the CMS, decide whether to populate the calendar, and use analytics before removing reachable workflows. No published records are changed by this code refactor. A deployment preview is needed to compare production timings with the live site under matching data and network conditions.

Standalone report: all styling is embedded, with no external fonts, scripts, or required assets. The implementation is included in the source repository. Production deployment has not been verified by this report. Deploy a preview to measure the production effect.
